Proposed Method: SAG

1

Start every merge with the paper's t.

2

After a long streak, use the paper's cost formula to compare t/2, t, 2t+2 and 0.

3

Switch to the cheapest value.

4

Reset t at the start of the next merge.

What SAG adds

No extra memory

No extra key comparisons

At most 4/3 of a streak's length per streak

O(log m) to adapt, only for streaks of 64+ items

Everything else is the same code as the base. SAG-C, a time-aware variant, was tried and rejected: it failed its safety check.

Streak-Adaptive Galloping for Natural Merge Sort

8 / 13

SAG changes only one thing: the rule for t. It starts from the paper's value, then after each long streak it asks the paper's own cost formula which of four values would have been cheapest, and moves to it. The what-if costs are pure arithmetic, so there is no extra memory and no extra key comparison. Each streak costs at most four thirds of its length. SAG-C was our second attempt, a time-aware version; it failed its safety check and is not our final candidate.
