## 3. Exception contract (Option A: basic exception guarantee)
* **Reproduction** (`stage3/exc/exc_repro.cpp` built against the ORIGINAL headers; log `stage3/logs/exc_repro_ORIGINAL.txt`): comparator throws on its k-th call for every k, 4 configurations x 3 minrun x 20 inputs: 84,623 cases, **32,069 left the array not a permutation** (elements lost and duplicated). Smallest case found: 3 elements, TimSort order + naive merge, throw at the 5th of 5 calls. Cause: the smaller run is copied to a temporary buffer and written back while merging; an exception left the unmerged part only in the buffer.
* **Guarantee before:** none (undocumented). **After (documented in the header):** if the comparator throws, the exception propagates and the array is a permutation of the input (no element lost or duplicated); order/stability after an exception are unspecified (basic guarantee, not strong). Run detection, binary insertion and the "already ordered" test cannot lose elements because they call the comparator before moving anything.
* **Change** (`src/natural_merge_sort.hpp`, +~25 lines): `GapGuard` copies the not-yet-merged remainder of the buffered run back into the output gap during unwinding (invariant: output position `k == i + j`, so the gap `[k, k+la-i)` holds exactly the buffered elements `L[i..la)`). `kMayThrow = !is_nothrow_invocable_r_v<bool, const Less&, const T&, const T&>`: for a `noexcept` comparator the guard is an empty type (no code). Chosen over Option B because static enforcement (`static_assert(noexcept)`) would break the frozen benchmark and test comparators, which are not declared `noexcept`.
* **Regression test:** `tests/test_exception.cpp` (built by `scripts/build.sh` as `build/test_exception`): same throw-at-every-call matrix -> **84,623 cases, 0 non-permutations**; plus a noexcept-comparator check. Reproduction log on the fixed header: `stage3/logs/exc_repro_FIXED.txt`.
* **Rerun of everything affected** (all on the patched header): `test_base` 1,502,829, `test_all` 2,100,389, `test_sag` 265,609, `test_sagt` 760,686, `test_exception` 84,624 checks, 0 failed (-O2); the same four plus `test_exception` under the hardened build (checked containers, UBSan trap, `-ftrapv`): 0 failed; red-team fuzz at -O2 (seed 20281020) and hardened (seed 20291020): 986,580 sorts, 10,057,802 checks, 0 failed each; the fuzz's throwing-comparator probe now reports **0 of 15** aborted sorts losing elements (was 4 of 15 in Stage 2).
* **Performance honesty:** (a) differential test (`stage3/exc/diff_counts.cpp`, original vs patched header, 216 runs over 6 policies x noexcept/non-noexcept comparators x 6 families x 3 sizes x 2 minrun): comparison counts, run/merge/block/move counters, buffer sizes and output hashes **identical**. (b) For noexcept comparators the generated assembly is not byte-identical: labels differ and one routine (the plain two-pointer merge) has a different instruction schedule. (c) Micro-benchmark (`stage3/exc/micro.cpp`, 1M integers, 3 inputs, 6 configurations, 5 alternating runs each, pinned): patched/original time ratios 0.86-1.02, no systematic change (noise level about +-5-10 % on the 18 ms nearly-sorted cases). So: **no measured performance effect, but code generation is not literally identical**; Stage-3 timings are taken on the patched header for every variant alike.
