### What `final_audit.py` actually checks (and does not)
Checks: A greps the paper-verification text for four strings; B rebuilds and runs the tests (parses counts); C compares demo output with the stored file; D re-runs `analyze.py` on the raw CSVs and requires the markdown to be **byte-identical** (so it proves reproducibility of the analysis *by the same code*, not its correctness - circular by design); E recomputes the manifest digest with `run_bench.py`'s own manifest code; F hashes the pre-addendum plan text; G hashes five library files; H counts cells and `ok` flags with hard-coded cell counts (90, 54); I file existence; J directory mtimes.
Does not check: duplicate or missing (cell, variant, repetition) rows, exit statuses in the run logs, that the logged commands equal the design, timing sanity, any number in the written reports, the round-2 plan hash (it only tests the pre-addendum prefix), whether variants share identical inputs, or stability in the plain/heavy regimes. It also **overwrites** `results/outputs/final_audit.txt` and deletes `build/` on every run. The stage-2 checker covers the missing items.

Further results: (a) `gallop_count` matches `gallop_tests_model` and returns the right block length in **all 925,911 cases** t <= 70, tail <= 160, every k, forward and backward (finite domain, not a proof); (b) the per-block bound "cost <= 4/3 x block length" holds on that domain with equality at (t=0, tail=4, k=2); per-merge comparisons / (a+b) observed: FixedT<0> 1.3317 (<= 4/3), SAG 1.003-1.018, polylog 1.000-1.018 (the families do not stress SAG's bound; the domain check does); (c) instrumentation: `Stats.comparisons()` equals externally counted comparator calls in 756 of 756 sorts and counting/non-counting builds sort identically; (d) SAG-C state machine: starts each merge at `t_max` with zero credit; one 10,000-block switches to `t = 0`; **50 single-element blocks** return it to `t_max` (cap/m); round-1 SAG has no recovery on cost-neutral short blocks (a block with tests <= its length changes nothing) - a design property, not a defect; (e) an **inconsistent (random-coin) comparator** in 540 sorts: no out-of-bounds write, output always a permutation (memory-safe for bad comparators); (f) **comparator that throws** (15 aborted sorts): in **4 of 15** the array afterwards is *not* a permutation (an element is lost/duplicated because merged elements live in the temporary buffer) - the code has no exception-safety guarantee (std::stable_sort offers the basic guarantee). Irrelevant for non-throwing comparators; documented as a limitation, **not changed** (no speculative changes).
Source review (read, not just tested): `merge_core` forward/backward tie handling is correct (ties to the buffered left run; backward uses the swapped comparator); block pointers cannot run past a run for any comparator (`gallop_count` returns <= len-1); `t = ceil_log2^2 <= 4096` so `t + step` cannot overflow; the PowerSort stack array of 128 entries is enough for 64-bit sizes; `memcpy`/`memmove` need `T` trivially copyable (enforced by `static_assert`); SAG-C calibration needs n >= 4096 (smaller arrays use the base policy); `measure_comparison_ns` uses a stride that wraps correctly for odd n. Divergences from the paper are those already documented (minrun insertion sort, one "already ordered" comparison, smaller-run buffering, no `min_gallop` state machine). **Verified** = tests above on stated domains; **inferred from the paper** = the stated asymptotic bounds (O(n + nH*), naive + O(n)); tests do not replace those proofs.
**Defects found and fixed: none** (so no separately checkpointed fix version was needed).
